# Требования: страница модуля ККД

Спецификация, по которой шла работа с ИИ-ассистентом. Источник — тестовое задание Frontend
(«Контроль качества данных по целям сотрудников»), mock API `moc_api_kkd` и справочник `UI-KIT.md` из него.

## 1. Что делает решение

Одна страница для руководителя и администратора. Она отвечает на два вопроса:
**стало лучше или хуже по сравнению с прошлым прогоном** и **что исправлять в первую очередь**.

Порядок блоков на странице — порядок этих вопросов:

1. **Шапка.** Выбор подразделения (дерево из `GET /api/meta`) и прогона (`GET /api/runs`).
   Выбор влияет на всю страницу.
2. **Контекст.** Путь подразделения, прогон и явная строка «Сравнение с RUN-007 от 26.10.2026»
   или «Первый прогон — сравнивать не с чем». Если между прогонами был упавший, он назван
   («RUN-006 пропущен: завершился с ошибкой»).
3. **Метрики** (`GET /api/kkd/summary`). Четыре главные крупно: доля корректных целей,
   покрытие каскадом, найдено проблем, критичные проблемы. Остальные пять — компактной строкой.
   У каждой: значение, прошлое значение, дельта со знаком и отдельно оценка «Лучше / Хуже / Без изменений /
   Без оценки» из поля `trend`.
4. **Найденные проблемы и дельта.** Счётчики «Новые / Сохраняются / Исправлены» и
   «Что исправлять первым»: проблемы по важности и по правилам, критичные сверху.
   Всё кликабельно и открывает таблицу с этим фильтром.
5. **Список проблем** (`GET /api/kkd/issues`): фильтры по правилу, важности, статусу дельты,
   сортировка, серверная пагинация.
6. **Карточка проблемы** (`GET /api/kkd/issues/{id}`) в модальном окне: что не так, факт и ожидание,
   рекомендация, цель / КР, ответственный, история по прогонам.

## 2. Ограничения

- Все числа — из ответов API как есть. Фронтенд не пересчитывает метрики, дельту и оценку.
- `null` — это «нет данных», а не 0. Ни в одном месте `null` не показывается нулём.
- Цвет — не единственный носитель смысла: у важности, статуса дельты, направления и оценки есть слово и значок.
- Визуал — по `UI-KIT.md`: тема antd собрана из токенов, hex-цвета есть только в `src/theme/theme.ts`.
- Адрес API — из окружения (`VITE_API_URL` для браузера, `API_PROXY_TARGET` для прокси), не в компонентах.
- Состояние выбора — в адресной строке: смена без перезагрузки, ссылка воспроизводима.
- Десктоп от 1280px.

## 3. Критерии приёмки

Формат: дано → действие → ожидаемый результат. Номер в скобках — где это проверяется.

### Контекст и сводка
- **П1.** Открыта страница без параметров → в адресе появляется `run=` последнего успешного прогона,
  показан «Корпоративный блок» и строка «Сравнение с RUN-007 от …».
- **П2.** Выбрано другое подразделение или прогон → вся страница обновляется без перезагрузки,
  адрес меняется, кнопка «Назад» возвращает прошлый выбор.
- **П3.** Метрика «Найдено проблем» выросла (`delta > 0`, `trend = worse`) → стрелка вверх, `+9 шт.`
  и оценка «Хуже» красным со значком. Доля корректных целей выросла → стрелка вверх и «Лучше» зелёным.
- **П4.** Метрика без направления (`higher_is_better = null`, «Активные цели») → дельта показана,
  оценка «Без оценки» нейтральным цветом, с подсказкой почему.
- **П5.** Разница процентов показывается в п.п. (`−25,5 п.п.`), у штучных метрик в скобках — `delta_pct` из API.
- **П6.** RUN-007 сравнивается с RUN-005 → рядом написано, что RUN-006 пропущен из-за ошибки.

### Граничные состояния
- **Г1. Первый прогон (RUN-001).** `previous`, `delta`, счётчики дельты — `null` → в карточках
  «Нет данных для сравнения», в шапке «Первый прогон — сравнивать не с чем», в блоке дельты
  объяснение вместо нулей; над таблицей — пояснение, что все проблемы отмечены как новые.
- **Г2. Упавший прогон (RUN-006).** Сводка и таблица не показываются. Видно сообщение с причиной
  из API и кнопки «Открыть RUN-007» и «Открыть RUN-005». Если API всё же ответил 409 `RUN_FAILED` /
  `RUN_IN_PROGRESS`, показывается то же самое.
- **Г3. Пустое подразделение (TX-NEW).** Активных целей 0, доли — `null` → пустое состояние
  «нет активных целей, метрики не рассчитываются, это не 0 проблем» и кнопка перехода к вышестоящему подразделению.
- **Г4. Загрузка.** Пока ждём ответ — скелетоны в форме будущих блоков; при смене страницы таблицы
  старые строки остаются со спиннером. Через 3 секунды — подпись «Сервер отвечает дольше обычного».
  Через 15 секунд — ошибка «Сервер отвечает слишком долго» с кнопкой «Повторить».
- **Г5. Ошибка сети / API не запущен.** Блок ошибки с понятным текстом и кнопкой «Повторить»;
  после восстановления API «Повторить» загружает данные без перезагрузки страницы.
- **Г6. Пустой результат фильтра.** «По выбранным фильтрам проблем нет» и кнопка «Сбросить фильтры».
  Подразделение без проблем (TX-SAL) → «В этом прогоне проблем не найдено».
- **Г7. Испорченная ссылка.** Неизвестные значения параметров отбрасываются; неизвестный прогон или
  подразделение → сообщение «не найдено» и кнопка «Открыть весь блок, последний прогон»; номер страницы
  больше последней → открывается последняя.

### Проблемы и карточка
- **Т1.** Клик по счётчику «Новые: 13» → таблица с фильтром `status=new`, прокрутка к таблице, фокус на её заголовке.
  Так же для важности и правила.
- **Т2.** Фильтры по правилу, важности и статусу дельты можно сочетать; любое изменение фильтра
  возвращает на первую страницу.
- **Т3.** Пагинация серверная: `limit` / `offset` из страницы и размера, всего — из `total`.
- **Т4.** Важность и статус дельты — тег со словом и значком.
- **Т5.** Клик по строке или по названию цели (доступно с клавиатуры) → карточка проблемы;
  `issue=` попадает в адрес, ссылку на карточку можно отправить.
- **Т6.** В карточке: описание правила, детали, факт и ожидание (`null` → «пусто (не заполнено)»),
  рекомендация, цель / КР, ответственный или «не назначен», первое обнаружение, история по каждому прогону
  («была / не было / прогон с ошибкой»), выбранный прогон выделен.

### Технические
- **Х1.** Один и тот же запрос не отправляется дважды (в том числе в StrictMode); устаревший запрос
  отменяется при смене параметров.
- **Х2.** `npm run build` проходит без ошибок TypeScript; `npm test` — зелёный.
- **Х3.** `docker compose up --build` поднимает фронтенд (порт 8080) и mock API (порт 8000).
- **Х4.** Базовая доступность: `header` / `main` / `section` с заголовками h1–h3, подписи у полей,
  `aria-label` у кнопок-иконок, видимый фокус, ссылка «Перейти к содержимому».
